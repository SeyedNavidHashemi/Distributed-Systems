# **Part 2 - Concurrency, Scheduling and Context-Switch**

This folder contains the code and results for the experiment corresponding to the second part of the first homework of the distributed computing course at the University of Tehran, designed to analyze the performance of concurrency and scheduling under various GOMAXPROCS and goroutine configurations, for both CPU-bound and mixed workloads.

## **File Descriptions**
**main.go:**
The core Go program that defines and executes the concurrency experiments. It supports cpu and mixed workloads and allows configurable GOMAXPROCS, number of goroutines, and iteration complexity via command-line flags. It outputs detailed metrics for each run.

**run_experiments.sh:**
A Bash script that automates the execution of the main.go program across a range of Workload Type (cpu, mixed), Goroutines (1, 2, 4, …, 64), and GOMAXPROCS (1, 2, and $(nproc) for all available cores). It appends the output of each experiment to results/results.txt.

**results/results.txt:**
This file stores the raw text output from all runs performed by run_experiments.sh. Each experiment’s metrics are appended to this file.

**results/results.csv:**
A CSV file generated by a Python parsing script (not included in this directory structure but used in analysis), which converts the raw results.txt data into a structured table format for easier analysis.

**results/*.png:**
These image files are visual representations (charts) of the experiment data from results.csv. They illustrate key performance patterns such as throughput, runtime, and the impact of different GOMAXPROCS and workload types.

## **How to Run the Experiments**
To execute all defined experiments and generate the raw results, follow these steps:

1- Navigate to the the current directory (*part2*). \
2- Once at the directory, make the script executable:
```
chmod +x run_experiments.sh
```
3- Run the experiment script:
```
./run_experiments.sh
```
This script will run main.go multiple times, varying the parameters, and all outputs will be saved into **results/results.txt**.

Note: Before running the script, ensure you have a results directory inside part1 (```mkdir -p results```). The *results.txt* file will be created/appended to within this directory.
